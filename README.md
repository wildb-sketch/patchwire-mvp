# Whassabi Android test APKs

[Download the latest Whassabi APK — watch and loudspeaker routing fix](https://github.com/wildb-sketch/patchwire-mvp/raw/refs/heads/android-test-download-20261117/whassabi-watch-speaker-fix.apk)

Install over the previous APK. Keep the watch paired, open **Room options → Audio output → Phone loudspeaker**. This choice is remembered across rooms and app restarts. Choose **Automatic (headsets)** again when you want automatic headset switching. The control is also available under Profile → Broadcast & Audio Hardware.

Automatic Android 12+ HFP routing now verifies the connected profile and excludes identified wearables rather than treating every communication-device port as earbuds. Failed Bluetooth routes stay excluded until actual connected-profile inventory changes or explicit output selection. Late communication-device callbacks cannot re-enable the failed watch. Phone output preference remains set while waiting for confirmation, and output-only recovery no longer advances microphone generation or repeatedly recreates AudioRecord.

Saved choices are Automatic (headsets), Phone loudspeaker, and Bluetooth audio. Phone loudspeaker ignores paired Bluetooth devices; explicit Bluetooth can include a wearable if selected. Unknown manufacturer watch metadata can be handled by the explicit phone choice. A listener can change output without microphone permission or opening capture, and speakers retain their mute intent. Bluetooth profile addresses/class metadata remain local and proxies are released on room shutdown.

Coverage includes watch-only connections, watch plus earbuds, stale failed-device callbacks, persisted phone selection, unverified speaker preferences, async profile shutdown, muted capture and output selection while native startup is pending.
